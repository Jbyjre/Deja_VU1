            Digital twin

            A live copy of your printer: the head, bed and spools move as the real ones do, and the print grows layer by layer in its real colours

            Modelled on Snapmaker's product photos of the U1 (front, sides, back and top) and its published figures (584 × 499 × 730 mm overall, a 276 × 293 mm plate, a 270 mm print cube). The body's own size (about 456 × 499 × 458 mm, measured from the photos), the spool and feeder positions, the dock spacing, the inside layout, the frame, motors and lead screw seen with the case off, and which side feeds which head are estimated. The print is drawn from its own G-code: the outside walls of every layer, in the colour loaded in the head that prints them. While it prints, the nozzle runs along that G-code and is checked against the printer's own position about four times a second, so the walls appear where and when they are laid.

                Slicer

                OrcaSlicer, installed by you. The dashboard runs its command line; it never downloads or installs anything.

                Optional

                For engines with packed presets, choose their matching unpacked profiles or use complete exported files. No profiles are downloaded.

                Worth knowing: this drives another program from outside. An OrcaSlicer update can change its command line; when that happens a slice here fails with Orca's own message in words, and it never quietly makes a bad file. Every slice is checked for real, printable layers before it's added, and records which Orca version made it.

                    Mixed layer heights

                    Detail where it shows, speed where it doesn't

                    Layer heights per head

                    The U1 can carry a different nozzle in each head. A small nozzle lays thin layers for crisp detail; a big one lays thick layers and finishes its parts in fewer passes. Choose what matters most and Deja Vu1 works out each head's layer so they always meet up. Nothing here can be set wrong: anything a nozzle can't print is greyed out, with the reason.

                    This plans layer heights; it does not slice a model. Nozzle limits come from Snapmaker's U1 machine profiles. To slice with it, save the same heights in Prepare → Tools & filaments and choose "Mixed" in a process profile; that needs an engine that lists per-head layer heights. Confirm Print checks each fitted nozzle before starting.

                    Photo-to-Print Studio

                    Make a colour-layered relief using your filament colours. This relief editor calculates in your browser.

                    Size

                    Detail is columns across. Near your nozzle's width (0.4 mm) per column is the finest a print can show.

                    Layers

                    Colours bottom to top, one per toolhead

                      TD (transmission distance) is how thick a layer must be before it hides what's under it. The numbers start as estimates from each colour's lightness. Measure your own filament for the truest result.

                        Start and check with a command If the dashboard stops answering or won’t start

                        Paste this into a new PowerShell (Windows) or Terminal (Mac, Linux) window. It starts Deja Vu1 in Documents if it isn’t running. Then that window shows “Deja Vu1 is ready and fully working”, or what is wrong and the block to paste next. Leave the window open: closing it stops Deja Vu1.

                        $dest = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'Deja_VU1'
if (-not (Test-Path "$dest\start.py")) { $ProgressPreference = 'SilentlyContinue'; Invoke-WebRequest 'https://github.com/Jbyjre/Deja_VU1/releases/latest/download/deja-vu1-update.zip' -OutFile "$env:TEMP\dejavu1.zip"; Expand-Archive "$env:TEMP\dejavu1.zip" -DestinationPath $dest -Force }
Set-Location $dest
if (Get-Command py -ErrorAction SilentlyContinue) { py -3 start.py } elseif (Get-Command python -ErrorAction SilentlyContinue) { python start.py } else { Write-Host 'Deja Vu1 needs Python 3.8 or newer: https://www.python.org/downloads/' }
                        [ -f ~/Documents/Deja_VU1/start.py ] || { curl -fL -o /tmp/dejavu1.zip https://github.com/Jbyjre/Deja_VU1/releases/latest/download/deja-vu1-update.zip && python3 -m zipfile -e /tmp/dejavu1.zip ~/Documents/Deja_VU1 && chmod +x ~/Documents/Deja_VU1/*.command ~/Documents/Deja_VU1/*.sh; }
cd ~/Documents/Deja_VU1 && python3 start.py

                          About Deja Vu1

                          A dashboard and print-preparation workspace for the Snapmaker U1.

                          Watch every U1, prepare plates and check each file before it prints. It runs on your computer, talks to the printer through Moonraker and slices with the Orca engine you install.

                          Check it yourself runs real checks in this copy. Nothing is sent and no printer is contacted.

                            Built with and on
                            • Moonraker and Klipper (GPL-3.0), and Snapmaker's U1 builds of them: talked to through Moonraker's published interface. The client and the test stand-in were written from reading their source; no code was copied.
                            • OrcaSlicer and Snapmaker Orca (AGPL-3.0): the slicing engine you install yourself; nothing is bundled. U1 facts were read from their profiles and source.
                            • 3DBenchy by Creative Tools: public domain (CC0); the sample prints are cut from it.
                            • Fonts: Bricolage Grotesque, Instrument Sans, IBM Plex Mono (SIL Open Font License).
                            • Snapmaker and U1 are Snapmaker's names. Deja Vu1 is independent and not made or endorsed by Snapmaker. It is written with the help of an AI coding assistant, from its owner's direction.

                            Your data is safe

                            Deja Vu1 keeps safety copies of everything it remembers (printers, spools, maintenance, the logbook, rules, queues and profiles) on this computer: every 6 hours, at start-up and before every update. If a file is ever damaged, it is repaired from them by itself.
