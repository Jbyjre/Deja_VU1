# Prove hardware and close the remaining compatibility gaps

Read CLAUDE.md, README Current status and docs/slicing-and-models.md first.
The owner is not a programmer. Keep the existing dependency-free architecture,
physical-tool identities, security checks, honest unknowns and source-preserving
save-as. No subagents. Private upstream study records must remain outside the repo.

Native four-tool preparation, per-printer camera time-lapse, installed profile
selection, editable plates, G-code inspection, colour tiles, measured layer
recipes and closed image reliefs exist. Real OrcaSlicer 2.4.2 on Linux has sliced
representative examples. This does not establish hardware safety or full format
compatibility. Extend these paths rather than building parallel interfaces.

The highest value remaining work is physical verification with an owner-approved
U1: protected/tagged filament refusal, colour/material readback and restart
persistence; camera reconnect and time-lapse across two printers; a tiny known-safe
print, pause/resume/cancel and queue handoff. Check phone touch, memory, battery,
accessibility and frame pacing on a real device. Keep watch-only checks separate
from physical commands and get consent for hardware actions.

Mixed nozzle sizes reach the real engine with one common layer height. An actual
0.4/0.6 mm preset emitted startup extrusion at X290 and was correctly blocked.
Find a hardware-verified startup configuration without broadening pre-flight
bounds or silently replacing printer commands. Different preferred layer heights
per head need a verified specialised engine and output comparison; the planner
alone is not a slicer. A converted three-plate fixture crashed Orca 2.4.2; improve
plate separation/import validation and inspect the engine fault before promising
multi-plate orchestration. Single-plate conversion has worked with installed U1
settings; it is not proof that every source preset is faithfully converted.

Preserve and correctly display subdivided face paint, textures and vendor
per-part settings, and keep edited AR aligned with the plate. Expand the profile
editor only where values reach actual engine options. Stress large, malformed and
painted files, import/export round trips, per-tool colour and material assignments.
Choose implementation freely; maintain explicit limits and refusal messages.

Prove colour recipes with physical measured swatches and identical process and
material settings, especially layer boundaries, temperatures and flow. Current
synthetic calibration checks verify geometry only. Improve calibration invalidation
when process settings change. Heightmaps are image reliefs, not geographic terrain;
geographic data, AI model services, feeder drivers and installers remain separate
products requiring source, hardware and licence decisions. The add-on guard is
read-only detection and never evidence that installation or a feeder is safe.

Selected-settings ZIP export includes tools and recipes, but is not full backup.
A complete backup/restore needs a versioned manifest, secrets policy, dry run,
conflict preview, atomic restoration and tested recovery while preserving the
original installation. A published update package and real Windows/macOS engine
and update checks remain outstanding. Refresh old feature crops and the owner's
75-second launch videos to show the actual native workflow and its limits.
